# mt5/atr — вероятность сделки по истории (для агента «Трейдер (демо)»)

Положить в репозиторий `ostatki` в папку `mt5/atr/`:
- `atr_context.py` — инструмент для агента
- `atr_prob_table.json` — таблица вероятностей (9 инструментов: EURUSD, GBPUSD, USDCHF, USDCAD,
  AUDUSD, NZDUSD, EURGBP, USDJPY, XAUUSD; 5-мин история 2010/2012 — 25.11.2026)
- `probs.py` — как посчитана таблица (нужны данные и backtest.py из Downloads/backtest на Mac)

Запуск (нужно `pip install dukascopy-python pandas`):
```
python mt5/atr/atr_context.py                              # ATR и растяжение по всем инструментам
python mt5/atr/atr_context.py XAUUSD buy 3530 3510 3560     # P(TP раньше SL) для сделки
python mt5/atr/atr_context.py --signals mt5/signals.csv     # проверить все сигналы файла
```
P(TP раньше SL) — доля таких же сделок в истории: тот же SL в дневных ATR, тот же R:R,
то же «растяжение» движения. Почти везде ≈ безубыточности 1/(1+R:R): это реалистичная база,
а не сигнал. Цены BID, спред не учтён. Учебная торговля на демо-счёте, не инвестиционный совет.

## Эксперимент «ATR-тест», режим 90%+ (atr_strategy.py)
`python mt5/atr/atr_strategy.py` — каждый запуск берёт свежие 5-мин свечи (Dukascopy, 20 дней), заново считает
дневной ATR (среднее 5 последних полных дней) и ноги движения по XAUUSD, EURUSD, GBPUSD, USDJPY на двух уровнях
(50% и 100% дневного ATR, как в ноутбуке; 25% убран 25.11.2026 — спред съедает маленькую цель) и печатает строки для `mt5/signals.csv`, если за последний час
сработало правило: цена прошла 1A от начала ноги → вход по движению.

По требованию владельца вход только с исторической вероятностью TP ≥ 90%: SL = 3A, TP = 0.1–0.3A
(подобрано по 2010–2026 для каждого инструмента и уровня, таблица PARAMS в скрипте).

| Уровень | Риск | P(TP раньше SL) | После спреда |
|---|---|---|---|
| 50% | 0.5% | 91.4–94.6% | −0.03…−0.05R, PF 0.41–0.65 |
| 100%D | 0.5% | 90.3–94.3% | −0.01…−0.02R, PF 0.72–0.91 |

**Фильтр «тренд + сессия» (с 25.11.2026):** покупки только при вчерашнем закрытии выше SMA50 дневных закрытий,
продажи — только ниже; вход только 03:00–12:00 по Нью-Йорку (13:00–22:00 Ташкента зимой). На истории
2019–2026 PF 0.59 → 0.67 (2010–2018: 0.56 → 0.58), сделок примерно вдвое меньше. Прибыльной стратегию не делает.

Почему так: 90% попаданий возможны только с целью в 10–30 раз меньше стопа; один стоп съедает 10–30 тейков,
а спред съедает часть маленькой цели. Это проверка вживую на демо-счёте, а не прибыльная стратегия.

`atr_prob_table.json` содержит и маленькие R:R (0.05–0.75), поэтому `atr_context.py` считает P и для сделок с целью
меньше стопа.

## Схема HorizonX (с 25.11.2026 вечер, решение владельца)
Из советника HorizonX (MT4) перенесено четыре вещи, без мартингейла:
- **Шаг лестницы** — 1/6 расстояния «вход → стоп» (HorizonX: доливка каждые 0.5 отката при стопе 3 отката). L6 — на 5/6 пути к стопу.
- **Рост лота** 1×, 1×, 2×, 2×, 3×, 3×. Общий риск сделки прежний (1%, ATR-тест 0.5%) и делится по весам:
  1% → 0.083 / 0.083 / 0.167 / 0.167 / 0.25 / 0.25 %. Удесятерения лота после стопа (StopLossCoef) НЕТ.
- **Цель** — откат на 1A от экстремума (HorizonX: CorrectionRange), т.е. 1/3 расстояния до стопа;
  `ladder.py ... auto ...` считает её сам. Советник переносит её от нового экстремума (TPFromExtreme).
  **Правило 90% отменено:** P(TP раньше SL) для L1 ≈ 75–81% при безубыточности ≈ 75–77% — по истории около нуля.
- **Торговые часы в советнике** (OfficeTrader 1.13): новые сигналы только 13:00–22:00 по Ташкенту
  (`SessionStartHour`, `SessionEndHour`, `SessionGMTOffset`); выставленные лимитки и позиции работают и вне окна.
⚠️ У L1/L2 риск теперь вдвое меньше прежнего (0.083%, в ATR-тесте 0.042%) — у золота лот чаще будет меньше минимального, советник такие ордера пропускает.

## Лестница: одна сделка = 6 ордеров (до 25.11.2026 вечер — см. выше) (ladder.py, с 25.11.2026)
L1 — по рынку (или по цене сигнала), L2…L6 — лимитки против движения с шагом 1/10 расстояния «вход → стоп»
(L6 — на полпути к стопу). Стоп и цель общие. Риск сделки делится на 6 (0.5% → 0.083% на ордер, 1% → 0.167%):
если стоп заберёт все шесть, убыток = прежний риск сделки. Правило 90% проверяется по L1; у дальних ордеров
вероятность TP ниже (цель дальше), но и прибыль больше.
```
python mt5/atr/ladder.py 20261125-1315-EURUSD EURUSD sell 1.0942 1.0992 1.0937 1 market "Комментарий"
```
id ордеров: `<база>-L1 … <база>-L6`, у ATR-теста `ГГММДД-ЧЧММ-СИМВОЛ-L1-A50` / `…-A100` (короткие: советник пишет в комментарий «AIO <id>», максимум 31 символ).
⚠️ У золота при широком стопе лот одного ордера может выйти меньше минимального 0.01 — проверить по логу советника.

## OfficeTrader 1.15 (с 26.11.2026, решение владельца: «золото тоже должно торговаться»)
- Если лот ордера меньше минимального (0.01), советник открывает минимальный лот, когда риск этого ордера ≤ `MinLotMaxOrderRiskPct` (0.5%)
  и риск всей сделки (все её позиции и лимитки) ≤ `MinLotMaxDealRiskPct` (1.5%). Иначе ордер пропускается, как раньше.
- Зачем: у золота при ATR ≈ 140 стоп 3A ≈ $210 (50%) / $420 (100%) на унцию, и ступени L1–L4 ATR-теста (0.042–0.083%) и
  дальние ступени агента выходили меньше 0.01 лота — торговались только L5–L6 (на 100% — только L6).
- ⚠️ Цена: фактический риск золотой сделки выше заявленного. Все 6 ступеней по 0.01 лота: ATR-тест 50% ≈ 0.75%, 100% ≈ 1.5% счёта
  (вместо 0.5%). Разбор считает R по фактическому риску ордеров; в журнале у таких ордеров пометка «минимальный лот: риск … вместо …».

## OfficeTrader 1.14 (с 26.11.2026)
- Время «сейчас по UTC» советник берёт по котировкам сервера, а не по часам компьютера: 25.11 часы ПК спешили ~15 мин,
  и рыночные L1 с окном ~20 мин сразу считались просроченными. При старте советник пишет в журнал, если часы расходятся > 2 мин.
- `CancelRestAfterClose = true`: когда все позиции сделки закрыты (TP, «цель от экстремума» и т.п.), её неисполненные
  лимитки снимаются — 25.11 лимитки EURUSD L4–L6 после TP сделки налились и ушли в стоп. В журнале: «сделка закрыта — снято неисполненных лимиток: N».
- Остальное как в 1.13 (торговые часы 13–22 Ташкента) и 1.12.

## OfficeTrader 1.12 (советник в MT5)
- `MaxOpenOrders = 30` вместо `MaxOpenTrades = 3` — помещаются лесенки по 6 ордеров.
- `TPFromExtreme = true`: если цена идёт против сделки, TP всех её открытых позиций и лимиток
  переносится от нового экстремума: продажа — новый максимум − исходная цель, покупка — новый минимум + цель.
  Сделка = символ + направление + одинаковый SL. Позиции в безубытке не трогает.
- Ордер, у которого лот меньше минимального, советник пропускает («минимальный лот даёт риск больше допустимого»).
